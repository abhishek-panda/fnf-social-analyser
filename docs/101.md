## 1. What is a Vision Model?

A **vision model** is an AI that has learned to "understand" images — not just see pixels, but recognise what's in them.

### How does it learn?

It's trained on millions of image + text pairs scraped from the internet:

```
🖼️  Photo of a red dress     →  📝  "woman wearing red floral dress"
🖼️  Photo of white trainers  →  📝  "Nike Air Force 1 white sneakers"
🖼️  Photo of a denim jacket  →  📝  "oversized blue denim jacket outfit"
```

After seeing hundreds of millions of these pairs, the model learns:
- What colours look like
- What garment types look like
- How visual features relate to words

### CLIP — the architecture we use

**CLIP** (Contrastive Language-Image Pre-training) has two encoders:

```
┌─────────────────────────────────────────────────────────────┐
│                        CLIP Model                           │
│                                                             │
│   🖼️  Image  ──►  [ Image Encoder ]  ──►  [1.2, -0.4, ...]  │
│                                                             │
│   📝  Text   ──►  [ Text Encoder  ]  ──►  [1.1, -0.5, ...]  │
│                                                             │
│   Trained so matching pairs produce SIMILAR output vectors  │
└─────────────────────────────────────────────────────────────┘
```

The key insight: **matching image and text produce similar numbers**. A photo of a red dress and the words "red dress" will produce very similar vectors after training.

### SigLIP vs CLIP

We use **SigLIP** (google/siglip-so400m) — same idea as CLIP but trained with a better loss function:

| | CLIP | SigLIP |
|---|---|---|
| Loss function | Softmax (compares across whole batch) | Sigmoid (each pair independently) |
| Image-text alignment | Good | Better |
| Colour/texture detail | Moderate | Better |

Think of it like:
- **CLIP** asks: *"Which caption best matches this image out of 1000?"* (relative)
- **SigLIP** asks: *"Does this caption match this image? Yes or No?"* (absolute)

The absolute judgement makes SigLIP better at fine-grained details — exactly what fashion needs.

## 2. What is an Embedding?

An **embedding** is a list of numbers that represents the meaning of something — an image, a sentence, or both.

### A simple analogy

Imagine placing every item of clothing on a map:

```
                    FORMAL
                      ▲
                      │
        Suit ●        │        ● Evening Gown
                      │
  CASUAL ◄────────────┼────────────► SMART
                      │
        Jeans ●       │        ● Chinos
                      │
                      ▼
                    CASUAL
```

On this 2D map, similar items are close together. An embedding is the same idea — but instead of 2 dimensions (x, y), it uses **768 dimensions** (for LAION ViT-L-14).

### What does an embedding look like?

```python
# A 768-dimensional embedding (truncated for display)
embedding = [0.023, -0.041, 0.118, 0.892, -0.334, 0.071, ...]
#            ↑       ↑       ↑      ↑       ↑
#          768 numbers, each between roughly -1.0 and 1.0
```

Each number captures some aspect of meaning — colour, texture, style, shape. No single number means anything on its own — the pattern across all 768 numbers is what matters.

### Why are embeddings useful?

Because **similar things have similar embeddings**.

```
"black leather jacket"  →  [0.12, -0.33, 0.87, ...]
"dark leather coat"     →  [0.11, -0.31, 0.85, ...]  ← very close!
"floral summer dress"   →  [-0.45, 0.72, -0.12, ...] ← very different
```

This means we can search by meaning, not just by keyword.

### Combined embeddings (image + text)

In this system, each post gets a **combined embedding** — the average of its image embedding and its text embedding:

```
📸 Post image  ──►  encode_image()  ──►  [0.3, 0.1, -0.4, ...]
                                                    +
📝 "obsessed with this jacket 🖤"
   clean → "black leather jacket"
           encode_text()          ──►  [0.2, 0.2, -0.3, ...]
                                                    ÷ 2
                                   ──►  [0.25, 0.15, -0.35, ...]  ← combined
```

This captures both what the post **shows** and what it **says**.

## 3. What is Cosine Similarity?

Cosine similarity is how we measure **how similar two embeddings are**.

### The intuition — angles between vectors

Think of each embedding as an arrow pointing in some direction in space.

```
        ▲
        │     → A  (black leather jacket post)
        │   ↗
        │ ↗  small angle = very similar
        │↗
        ├──────────────────────►
        │↘
        │  ↘  large angle = very different
        │    ↘
        │      → B  (floral summer dress post)
```

- **Small angle** between two arrows = similar meaning = high cosine similarity
- **Large angle** = different meaning = low cosine similarity

### The maths

Given two vectors **A** and **B**:

```
                    A · B
cos(θ) = ─────────────────────────
              ‖A‖  ×  ‖B‖
```

Where:
- `A · B` is the **dot product** — multiply corresponding numbers and sum them
- `‖A‖` is the **magnitude** (length) of vector A
- `‖B‖` is the **magnitude** of vector B

### Worked example (simplified to 3 dimensions)

```
Product embedding:  A = [0.8,  0.4,  0.2]
Post embedding:     B = [0.7,  0.5,  0.1]

Step 1 — Dot product (A · B):
  (0.8 × 0.7) + (0.4 × 0.5) + (0.2 × 0.1)
= 0.56 + 0.20 + 0.02
= 0.78

Step 2 — Magnitude of A (‖A‖):
  √(0.8² + 0.4² + 0.2²)
= √(0.64 + 0.16 + 0.04)
= √0.84
= 0.917

Step 3 — Magnitude of B (‖B‖):
  √(0.7² + 0.5² + 0.1²)
= √(0.49 + 0.25 + 0.01)
= √0.75
= 0.866

Step 4 — Cosine similarity:
  0.78 / (0.917 × 0.866)
= 0.78 / 0.794
= 0.982  ← very similar! (close to 1.0)
```

### Score interpretation

| Score | Meaning |
|---|---|
| `1.0` | Identical vectors — perfect match |
| `0.8 – 1.0` | Very similar — strong match |
| `0.5 – 0.8` | Somewhat similar — possible match |
| `0.3 – 0.5` | Weak similarity — marginal |
| `0.0 – 0.3` | Not similar — filtered out |
| `< 0` | Opposite meaning |

In this system, `SIMILARITY_THRESHOLD=0.3` means anything below 0.3 is discarded.

### Why cosine and not euclidean distance?

Euclidean distance measures how far apart two points are. Cosine similarity measures the **angle** between them — it ignores magnitude.

```
‖A‖ = [2.0, 4.0]      large vector
‖B‖ = [0.5, 1.0]      small vector — but same direction as A!

Euclidean distance: 3.35  (seems far apart)
Cosine similarity:  1.0   (identical direction = identical meaning ✅)
```

This matters for embeddings because the model may produce vectors of different magnitudes — but the direction is what encodes meaning.

### pgvector's notation

In PostgreSQL with pgvector, cosine similarity is computed as:

```sql
-- pgvector returns cosine DISTANCE (0 = identical, 2 = opposite)
-- We convert to similarity by subtracting from 1
1 - (post_embeddings.embedding <=> $1::vector) AS score
```

The `<=>` operator is pgvector's cosine distance operator. Subtracting from 1 gives us a similarity score where 1.0 = perfect match.

## 4. How It All Fits Together

Here's the full pipeline from an Instagram post to a search result:

### At ingest time (feed-collector → embedding-service)

```
📸 Instagram post
   image: 17888291706617649.jpg
   caption: "obsessed 🖤 #fandfclothing leather bomber"
        │
        ▼
CaptionService.clean()          ← Ollama LLM strips noise
   "black leather bomber jacket"
        │
        ▼
CLIPService.encode_text()       ← text encoder
   [0.12, -0.33, 0.87, ...]    (768 numbers)
        │
CLIPService.encode_image()      ← image encoder
   [0.15, -0.28, 0.91, ...]    (768 numbers)
        │
        ▼
average(text, image)            ← combine both signals
   [0.13, -0.30, 0.89, ...]    (768 numbers)
        │
        ▼
stored in post_embeddings table
```

### At search time (image-search → embedding-service → pgvector)

```
🛒 Tesco product query
   tpnb: "323951665"
   image: product-photo.jpeg
   caption: "F&F Faux Leather Funnel Neck Jacket"
        │
        ▼
Same pipeline → product embedding
   [0.11, -0.31, 0.88, ...]    (768 numbers)
        │
        ▼
pgvector cosine similarity search
   1 - (stored_embedding <=> product_embedding)
        │
        ▼
Ranked results:
   Post A: score 0.91 ✅ (black leather jacket photo)
   Post B: score 0.74 ✅ (dark coat photo)
   Post C: score 0.21 ❌ (filtered — below threshold)
```

### Why does this work?

Because the vision model was trained so that **similar things produce similar vectors**. A Tesco product photo of a black leather jacket and an Instagram post of someone wearing a black leather jacket will produce embeddings that point in a similar direction in 768-dimensional space — even though they're completely different images from completely different sources.

The model learned this not by being told "leather jacket = similar to leather jacket" — but by seeing millions of image-text pairs and learning the underlying visual-semantic structure of the world.
